# 微服务日志系统

## 概述

XEERP-FASTAPI 微服务架构采用统一的日志管理系统，所有服务的日志统一输出到项目根目录的 `logs/` 文件夹下，便于集中管理和分析。

### 核心特性

- **统一存储**：所有微服务日志集中存储在 `logs/` 目录
- **按服务分离**：每个服务生成独立的日志文件
- **日志分级**：同时输出 Info 日志和 Error 日志到不同文件
- **自动轮换**：每日凌晨自动轮换日志文件
- **自动压缩**：历史日志自动压缩为 `.zip` 格式节省空间
- **双重输出**：同时输出到文件和控制台，便于开发调试

## 日志文件说明

### 主日志文件 `{service_name}.log`

包含该服务所有级别的日志信息：

- `DEBUG`：调试信息
- `INFO`：一般信息（如服务启动、请求处理）
- `WARNING`：警告信息
- `ERROR`：错误信息
- `CRITICAL`：严重错误

### 错误日志文件 `{service_name}.error.log`

专门记录错误和严重错误信息，便于快速定位问题：

- `ERROR`：错误信息
- `CRITICAL`：严重错误

## 日志格式

日志采用统一格式，包含时间戳、日志级别、模块位置和消息内容：

```
2026-05-20 17:36:31,206 | INFO | <module>:<funcName>:<lineno> - 消息内容
```

### 格式字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间戳 | 日志记录时间 | `2026-05-20 17:36:31,206` |
| 日志级别 | INFO/WARNING/ERROR 等 | `INFO` |
| 模块位置 | 模块名:函数名:行号 | `server:lifespan:15` |
| 消息内容 | 日志描述信息 | `[START] product-service starting...` |

## 日志轮换机制

### 轮换规则

- **触发时间**：每日凌晨 00:00:00
- **轮换间隔**：1 天
- **保留天数**：30 天

### 轮换流程

1. **时间触发**：当时间到达午夜（`when='midnight'`）时触发轮换
2. **文件重命名**：将当前日志文件重命名为带日期后缀的备份文件
   - `system.log` → `system.log.2026-05-19`
3. **自动压缩**：备份文件自动压缩为 `.zip` 格式
   - `system.log.2026-05-19` → `system.log.2026-05-19.zip`
4. **新文件创建**：创建新的日志文件继续写入
5. **清理旧文件**：超过 30 天的压缩文件自动删除

### 压缩文件命名

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 主日志压缩 | `{service}.log.{date}.zip` | `system.log.2026-05-01.zip` |
| 错误日志压缩 | `{service}.error.log.{date}.zip` | `system.error.log.2026-05-01.zip` |

## 使用方法

### 1. 服务中引入日志记录器

在每个微服务的 `core/logger.py` 中配置：

```python
"""
Service Logger Configuration
"""

import sys
import os

# 添加项目根目录到路径
sys.path.append(os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))))

from utils.log_util import setup_logger

# 创建服务日志记录器
logger = setup_logger('service_name')
```

### 2. 服务入口文件使用

```python
from core.logger import logger

@asynccontextmanager
async def lifespan(app: FastAPI):
    logger.info("Starting service...")
    await init_db()
    logger.info("Service started successfully")
    yield
    logger.info("Stopping service...")
```

### 3. 业务代码中记录日志

```python
from core.logger import logger

# 记录信息
logger.info("User login successful: user_id=123")

# 记录警告
logger.warning("Rate limit exceeded: ip=192.168.1.1")

# 记录错误
logger.error(f"Database query failed: {str(e)}")

# 记录严重错误
logger.critical("System shutdown required")
```

### 4. 获取日志统计信息

```python
from utils.log_util import get_log_stats

# 获取服务的日志统计
stats = get_log_stats('order')

print(f"主日志: {stats['main_log']['size_human']}")
print(f"错误日志: {stats['error_log']['size_human']}")
print(f"最后修改: {stats['main_log']['last_modified']}")
```

### 5. 手动触发日志轮换

```python
from utils.log_util import rotate_and_compress

# 手动触发日志轮换和压缩
rotate_and_compress('order')
```

### 6. 清理旧日志

```python

# 清理 30 天前的日志（默认）
clean_old_logs(days_to_keep=30)

# 清理 7 天前的日志
clean_old_logs(days_to_keep=7)
```

### 7. 获取日志文件路径

```python

# 获取主日志路径
```

## API 端点（可选）

可以在系统中添加日志查看 API：

```python
from fastapi import APIRouter
from utils.log_util import get_log_stats, clean_old_logs, LOG_DIR
from pathlib import Path

router = APIRouter(prefix="/api/logs", tags=["日志管理"])

@router.get("/stats/{service_name}")
async def get_service_log_stats(service_name: str):
    """获取服务日志统计"""
    return get_log_stats(service_name)

@router.get("/files")
async def list_log_files():
    """列出所有日志文件"""
    files = []
    for f in LOG_DIR.glob("*"):
        if f.is_file():
            files.append({
                'name': f.name,
                'size': f.stat().st_size,
                'modified': f.stat().st_mtime
            })
    return files

@router.post("/rotate/{service_name}")
async def rotate_service_logs(service_name: str):
    """手动触发日志轮换"""
    from utils.log_util import rotate_and_compress
    rotate_and_compress(service_name)
    return {"message": f"{service_name} logs rotated"}

@router.post("/clean")
async def clean_old_compressed_logs(days: int = 30):
    """清理旧日志"""
    clean_old_logs(days_to_keep=days)
    return {"message": f"Cleaned logs older than {days} days"}
```

## 最佳实践

### 日志级别使用规范

| 级别 | 使用场景 |
|------|---------|
| `DEBUG` | 开发调试信息，仅开发环境启用 |
| `INFO` | 正常业务流程：服务启动、请求处理、数据操作成功 |
| `WARNING` | 潜在问题：业务逻辑异常、配置警告、资源使用警告 |
| `ERROR` | 错误：操作失败、异常捕获、第三方服务调用失败 |
| `CRITICAL` | 严重错误：系统不可用、数据丢失风险、服务崩溃 |

### 日志记录最佳实践

**推荐做法：**
```python
# ✅ 好的日志记录
logger.info(f"Order created successfully: order_id={order_id}, amount={amount}")
logger.warning(f"User {user_id} attempted to access unauthorized resource")
logger.error(f"Failed to process payment: order_id={order_id}, error={str(e)}")

# ✅ 使用结构化数据（推荐）
import json
logger.info(f"Request processed: {json.dumps({'user_id': user_id, 'action': 'login'})}")

# ✅ 在异常处理中记录日志
try:
    await db.execute(query)
except Exception as e:
    logger.error(f"Database operation failed: {str(e)}", exc_info=True)
    raise
```

**不推荐做法：**
```python
# ❌ 避免冗余信息
logger.info("Processing...")  # 太模糊
logger.info("Function called")  # 无意义

# ❌ 避免在日志中记录敏感信息
logger.info(f"User password: {password}")  # 安全风险

# ❌ 避免日志过多
for i in range(10000):
    logger.info(f"Processing item {i}")  # 产生大量日志
```

### 日志文件管理

1. **定期监控日志大小**：避免单个日志文件过大
2. **设置合理的保留天数**：根据磁盘空间和合规要求调整
3. **使用日志分析工具**：如 ELK、Graylog 等进行日志分析
4. **设置日志告警**：监控 ERROR 日志数量，异常时告警

## 故障排查

### 日志文件权限问题

如果遇到无法写入日志文件的问题：

```bash
# Linux/Mac
chmod 644 logs/*.log
chmod 644 logs/*.zip

# Windows
# 以管理员身份运行
```

### 日志文件被占用

确保没有其他进程锁定日志文件：

```bash
# Windows
Handle.exe 或 Process Explorer

# Linux
lsof logs/system.log
```

### 日志格式异常

检查日志格式配置是否正确，确保 `logging.Formatter` 格式字符串一致。

## 总结

XEERP-FASTAPI 微服务架构的日志系统提供了完整、高效、可扩展的日志管理能力：

- **集中管理**：所有服务日志统一存储，便于集中监控和分析

- **易于使用**：简单的 API 设计，方便集成到各个服务

通过统一的日志系统，可以实现：
- 实时监控服务运行状态
- 快速定位和排查问题
- 满足审计和合规要求
- 支持日志分析和数据挖掘
