## 一、中间件注册入口

```python
# system/middlewares/handle.py
def handle_middleware(app: FastAPI):
    add_cors_middleware(app)   # CORS
    add_gzip_middleware(app)   # GZip
    add_trace_middleware(app)  # Trace（trace_id 注入日志上下文）
```

每个微服务 `server.py` 在 `register_routers` 之后调用 `handle_middleware(app)` 统一注册。

## 三、GZip 中间件

```python
# system/middlewares/gzip_middleware.py
app.add_middleware(GZipMiddleware, minimum_size=500)
```

## 四、Trace 中间件（自研 ASGI）

```python
# system/middlewares/trace_middleware/middle.py
class TraceASGIMiddleware:
    async def __call__(self, scope, receive, send):
        if scope['type'] != 'http':
            await self.app(scope, receive, send)
            return
        async with get_current_span(scope) as span:
            handle_outgoing_receive = await self.my_receive(receive, span)
            async def handle_outgoing_request(message):
                await span.response(message)
                await send(message)
            await self.app(scope, handle_outgoing_receive, handle_outgoing_request)
```

**核心功能**：
1. 为每个 HTTP 请求生成唯一 `trace_id`（或从请求头 `X-Trace-Id` 取得）；
2. 将 `trace_id` 注入 contextvars，让日志自动携带；
3. 记录请求/响应生命周期事件（`request_before` / `request_after` / `response`）。

## 五、全局异常处理

### 5.1 异常类层次

```
BaseException（项目自定义根）
├── LoginException        (401)
├── AuthException         (403)
├── PermissionException   (403)
├── ServiceException      (500)
├── ServiceWarning        (200, code=-1)
└── ModelValidatorException (422)
```

每个异常携带 `error_code`（枚举）、`message`、`data`、`http_status`、`details`。

### 5.2 注册逻辑（`system/core/handle.py`）

```python
def handle_exception(app: FastAPI):
    @app.exception_handler(AuthException)
    async def auth_exception_handler(request, exc):
        return ResponseUtil.unauthorized(data=exc.data, msg=exc.message)

    @app.exception_handler(ServiceException)
    async def service_exception_handler(request, exc):
        logger.error(exc.message)
        return ResponseUtil.error(data=exc.data, msg=exc.message)

    @app.exception_handler(Exception)
    async def exception_handler(request, exc):
        logger.exception(exc)
        return ResponseUtil.error(msg=str(exc))
```

### 5.3 统一响应体

所有异常最终转化为 `ResponseUtil` 的统一 JSON：

```json
{
  "code": -1,
  "msg": "业务异常: ...",
  "success": false,
  "time": "2026-05-15T10:00:00"
}
```

> HTTP 状态码始终 200（业务异常不使用 4xx/5xx），前端通过 `code` 字段判断成功/失败。
> 仅 HTTPException 会原样返回 HTTP 状态码。

## 六、在业务中抛出异常

```python
from core.exception import ServiceException, LoginException

# 登录模块
if not user:
    raise LoginException(message='用户不存在')

# 业务模块
if stock < 0:
    raise ServiceException(message='库存不足')
```

## 七、网关 vs 业务服务的中间件差异

| 特性 | Gateway | 业务服务（system/product...） |
| ---- | ------- | ----------------------------- |
| CORS | ✅ | ✅（冗余但无害） |
| GZip | ❌ | ✅ |
| Trace | ❌（建议加入） | ✅ |
| Auth | ✅ 自研 `AuthMiddleware` | ❌（依赖网关已校验） |
| Logging | ✅ 自研 `LoggingMiddleware` | 内置于 Trace Span |
| 限流 | ✅ slowapi | ❌ |
| 全局异常 | ❌（仅 HTTPException） | ✅ `handle_exception(app)` |
