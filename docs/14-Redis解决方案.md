# ERP 用 Redis：数据准确性、可靠性、安全全面解答

## 核心结论

**合理规范使用 Redis，完全不会出现数据不准；乱用缓存策略、无同步机制，一定会出现脏数据、数据不一致**
Redis 本身是高性能内存数据库，**不产生业务数据错误**，数据不准全是**业务缓存策略、读写时序、同步逻辑**写错导致。

---

## 一、先分清：ERP 里两类数据，Redis 用法完全不同

### 1\. 强一致性核心业务数据（绝对不能单纯放 Redis 做主存储）

库存金额、出入库单据、应收应付、财务对账、商品库存数量、采购销售订单
✅ **原则**：

- **MySQL 做主持久化数据源**（唯一真实数据源）

- Redis 只做**查询缓存、临时计数、流量削峰**

- 最终对账、结账、财务核算**只以 MySQL 为准**

### 2\. 弱一致性热点静态数据（放心全量缓存）

数据字典、系统菜单、角色权限、商品分类 / 品牌 / 单位、系统配置、省市区
✅ **原则**：全量缓存 Redis，大幅提速，变更主动清缓存即可

---

## 二、Redis 为什么会出现**数据不准确**？（ERP 最常见 5 大原因）

### 1\. 缓存更新策略错误（最高发）

错误逻辑：
先更新 Redis → 再更新 MySQL
网络抖动 / 程序异常 → Redis 改了，数据库没改 → **数据永久不一致**

**ERP 强制标准策略（杜绝不一致）**

1. 增 / 删 / 改业务数据：**先改 MySQL，再删除 Redis 缓存**

2. 查询数据：**先查 Redis，无数据再查 MySQL，回写 Redis**

> 口诀：**写库删缓存，读库写缓存**
> 
> 

### 2\. 缓存过期时间不合理

- 永久缓存静态数据，后台修改后台字典 / 菜单，前端永远读旧缓存

- 热点业务缓存过期太长，业务变更后长期展示旧数据

### 3\. 高并发下读写冲突

ERP 大量同时下单、出库、入库：
多线程同时查库存→都走旧缓存→**超卖、库存扣减错误**

### 4\. Redis 宕机 / 重启丢失临时数据

未开启持久化，Redis 重启后内存计数清空，临时库存计数错乱。

### 5\. 分布式环境缓存不同步

微服务多实例部署，A 服务改数据清缓存，B 服务依旧读取本地旧缓存。

## 三、ERP 项目 彻底解决 Redis 数据不准确 全套方案

### 1\. 统一读写规范（强制执行）

1. **所有正式业务单据、财务数据、库存台账 只落库 MySQL**

2. Redis 只做**加速查询**，不做主数据源

3. 任何业务校验最终校验**MySQL 数据库**

### 2\. 库存高并发精准控量（ERP 核心，零误差）

禁止直接缓存库存静态值，改用**Redis 原子计数器**

1. 真实库存存 MySQL

2. 前端高并发下单，先用`decrby`原子预扣 Redis 库存

3. 预扣成功再走数据库事务正式扣减

4. 业务失败用`incrby`回补 Redis 数量
**优点：无并发冲突，库存绝对精准，不会超卖、不会多扣**

### 3\. 缓存清除机制（三种兜底）

1. **主动清除**：后台编辑商品 / 分类 / 字典 / 菜单 → 代码直接 DEL 对应 Redis key

2. **过期兜底**：所有业务缓存统一设置过期时间（30 分钟～2 小时），自动淘汰脏数据

3. **定时全量刷新**：凌晨低峰自动刷新全量商品、基础资料缓存

### 4\. 开启 Redis 持久化，保障数据可靠性

修改`redis\.conf`

```conf
# RDB快照
save 60 1000
# AOF日志（防丢数）
appendonly yes
appendfsync everysec
```

重启生效，重启后计数数据不丢失。

### 5\. 微服务统一缓存中心

所有 ERP 微服务**共用同一套 Redis 集群**，不本地缓存，全局缓存统一。

### 6\. 禁止危险操作

1. 禁止把**财务金额、对账数据、结算数据**直接存在 Redis 持久使用

2. 禁止使用 Redis 数据直接做财务统计、月结、年终盘点

3. 禁止长业务流程依赖 Redis 中间状态

---

## 四、数据安全性保障（Redis\+ERP）

1. **Redis 设置密码**，禁止外网直连访问

2. 内网部署，只允许网关、后端服务内网调用

3. 登录 Token、用户权限存放 Redis，设置自动过期，实现自动下线

4. 敏感业务接口搭配**Redis 接口限流**，防恶意刷单、批量下单攻击

5. 用户登录凭证 Redis 存储，支持强制踢人、账号锁定

---

## 五、最终总结回答你的核心疑问

1. **只用 Redis 存缓存、不做主库 → 不会出现数据不准确**

2. **只要遵循：写库删缓存、查询走缓存、库存用原子计数、财务以 MySQL 为准**，ERP 业务 100% 数据精准

3. **数据不可靠、不准确，全部是使用方式错误，不是 Redis 本身问题**

4. ERP 正式盘点、财务对账、月结核算**一律以 MySQL 为准**，Redis 只负责提速

## 极简落地守则（开发直接照抄）

1. 静态基础数据 → 全缓存 Redis，改即清缓存

2. 商品列表、详情 → 缓存加速，修改删除缓存

3. 实时库存 → Redis 原子预扣，MySQL 最终落账

4. 订单、采购、销售、财务单据 → 只存 MySQL，Redis 仅做查询加速

5. 所有数据对账、统计、结算 **放弃 Redis，直连数据库**
