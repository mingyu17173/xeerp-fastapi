# 02 · 快速开始

本章帮你在本地把 XEERP-FASTAPI 跑起来，并完成第一次登录调用。

---

## 一、环境准备

| 组件 | 版本要求 | 必装 |
| ---- | -------- | ---- |
| Python | 3.12+ | ✅ |
| MySQL | 8.0+ （或 PostgreSQL 14+） | ✅ |
| Redis | 7.0+ | ✅ |
| Node.js | 18+ （前端 `web-ui` 时需要） | ⭕ 可选 |
| Git | latest | ✅ |

> Windows 下 `asyncmy` 编译需要 VC++ Build Tools；推荐直接使用 wheel：`pip install asyncmy --only-binary=:all:`。

---

## 二、克隆与依赖安装

```bash
git clone <仓库地址>
cd XEERP-FASTAPI

# 推荐使用虚拟环境
python -m venv .venv
.\.venv\Scripts\activate            # Windows
# source .venv/bin/activate         # Linux/macOS

pip install -r requirements.txt
# 各微服务可能还需要：
pip install fastapi-pagination "slowapi" "apscheduler" "pydantic-settings" "pydantic-validation-decorator" "loguru"
```

> 若安装过程中提示缺包，按报错补装即可。`requirements.txt` 是最小集，业务模块零散依赖在各服务运行时按需补齐。

---

## 三、配置文件

项目根目录已提供 `.env.example`，复制为 `.env` 后按本地实际情况修改：

```bash
copy .env.example .env             # Windows
# cp .env.example .env             # Linux/macOS
```

关键配置：

```ini
APP_HOST=0.0.0.0
APP_PORT=1999                      # 注意：每个服务在 core/env.py 中各自定义独立端口
APP_RELOAD=true

# JWT
JWT_SECRET_KEY=<请改成自己的随机串>
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=1440

# 主/从数据库（system 等服务读取）
DB_MASTER_HOST=192.168.x.x
DB_MASTER_PORT=3307
DB_MASTER_USERNAME=root
DB_MASTER_PASSWORD=********
DB_MASTER_DATABASE=xetms

# Redis
REDIS_HOST=192.168.x.x
REDIS_PORT=6379
REDIS_DATABASE=2
```

各服务 `core/env.py` 中定义了独立 `app_port`，请确认端口与 [01-项目概览 §五](./01-项目概览.md#五服务清单与端口) 一致。

## 四、数据库初始化

`system` 服务启动时会自动执行 `Base.metadata.create_all`：

```python
# system/core/get_db.py
async with async_engine.begin() as conn:
    await conn.run_sync(Base.metadata.create_all)
```

因此首次启动 `system` 即可建表。**若需初始数据**（管理员账号、字典、菜单），可向团队索取 `init_data.sql` 单独导入。

## 五、启动服务

### 5.1 启动顺序（推荐）

```
system (8001) → product/stock/partner (8002/8003/8007) → production/order (8004/8008)
              → report/approval/purchase (8005/8006/8009) → gateway (8000)
```

> 网关最后启动以确保下游服务已就绪；下游服务相互独立可并行启动。

### 5.2 启动命令

每个微服务都有自己的 `run.py`：

```bash
# 终端 1：系统服务
cd system && python run.py

# 终端 2：商品服务
cd product && python run.py

# 终端 3：库存服务
cd stock && python run.py

# 终端 4：生产服务
cd production && python run.py

# 终端 5：报表服务
cd report && python run.py

# 终端 6：网关
cd gateway && python run.py
```

### 5.3 一键脚本（待完善）

### 5.4 生产部署（Linux + systemd）

参考 [`doc/erp-gateway.service`](../doc/erp-gateway.service) 与 [`doc/auto-restart.sh`](../doc/auto-restart.sh)，把每个微服务注册为独立 systemd unit，由 `gunicorn` 启动并启用 `auto-restart.sh` 监控防卡死。

## 七、第一次登录调用

> 默认账号一般为 `admin / admin123`（具体以你导入的 `init_data.sql` 为准）

### 7.1 调用登录接口

```bash
curl -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=admin123"
```

响应（节选）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": { "access_token": "eyJhbGciOiJIUzI1NiIs...", "token_type": "bearer" },
  "success": true
}
```

### 7.2 调用受保护接口

```bash
curl http://localhost:8000/api/user/list \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
```

> 网关会在 `AuthMiddleware` 中校验 JWT，校验通过后 `request.state.user = payload` 转发至下游服务。

## 八、启动前端（可选）

```bash
cd web-ui
yarn --registry=https://registry.npmmirror.com
yarn dev    # 开发: http://localhost:80
yarn build:prod
```

`web-ui` 是 RuoYi-Vue3 模板二次开发，需要把其默认 baseURL 改成 `http://localhost:8000`（网关地址）。

## 九、常见问题

| 现象 | 排查 |
| ---- | ---- |
| `ImportError: No module named 'core'` | 必须从服务目录内 `python run.py` 启动，不要从项目根直接跑 |
| `asyncmy` 安装失败 | `pip install asyncmy --only-binary=:all:` 或换 wheel 镜像 |
| 启动时 `redis 用户名或密码错误` | 确认 `.env` 中 `REDIS_USERNAME/PASSWORD` 与服务端一致 |
| 网关报 404 "未找到对应的服务" | 检查 `gateway/router/gateway_router.py` 中是否登记了对应前缀 |
| Swagger 登录后 token 显示 undefined | 这是已知兼容，登录接口对来自 `/docs` 的请求做了特殊处理 |
