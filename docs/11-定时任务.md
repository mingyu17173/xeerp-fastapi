## 一、技术选型

| 组件 | 说明 |
| ---- | ---- |
| `APScheduler` | Python 生态最成熟的定时任务框架 |
| `AsyncIOScheduler` | 配合 FastAPI 事件循环 |
| `MyCronTrigger` | 自定义 6/7 位 Cron（含秒位、`?` `L` `W` `#` 语法） |
| `JobStore` | 支持 Memory / SQLAlchemy / Redis 三种存储 |
| `Executor` | AsyncIO（默认）+ ProcessPool（CPU 密集） |

## 二、初始化流程

```python
# system/server.py → lifespan
await SchedulerUtil.init_system_scheduler()
```

`init_system_scheduler()` 内部：

1. `scheduler.start()` — 启动调度循环
2. 从 DB 加载已有任务列表（`JobDao.get_job_list_for_scheduler`）
3. 逐一移除旧任务并重新添加（保证重启时不重复）
4. 注册事件监听器 `scheduler_event_listener`（记录执行日志）

## 三、Cron 表达式规范

```
秒 分 时 日 月 周 [年]
0  0  2  *  *  ?       — 每天凌晨 2:00
0  30 9  L  *  ?       — 每月最后一天 9:30
0  0  10 ?  *  1#3     — 每月第三个周一 10:00
```

- `?`：不指定（日/周互斥）
- `L`：最后一天（日 = last day；周 = last X）
- `W`：最近工作日
- `#`：第几个星期几

由 `MyCronTrigger.from_crontab()` 解析。

## 五、任务函数注册

任务目标函数放在 `system/script_task/` 目录下，模块导入时自动被 `get_scheduler.py` 中 `import script_task` 注册。

```python
# system/script_task/__init__.py
from .my_task import hello_task

# system/script_task/my_task.py
async def hello_task():
    print("Hello from scheduler!")
```

数据库字段 `invoke_target` 存储可 eval 的函数引用（如 `script_task.my_task.hello_task`），APScheduler 通过 `eval(invoke_target)` 获取函数对象。

> **安全警告**：`eval(invoke_target)` 有注入风险，生产环境建议改为白名单映射。

## 六、执行日志

事件监听器 `scheduler_event_listener` 在每次任务执行后：
- 获取任务元信息（名称、组、表达式、参数）
- 判断是否异常（`event.exception`）
- 构造 `JobLogModel` 写入数据库
- 日志记录执行时间、状态、异常信息

## 七、JobStore 选择

| Store | 用途 |
| ----- | ---- |
| `default` (Memory) | 临时任务、一次性执行 |
| `sqlalchemy` | 持久化定时任务（重启恢复） |
| `redis` | 分布式多实例需要共享调度状态 |

通过任务的 `job_group` 字段映射到对应 store。

---

## 八、扩展建议

1. **分布式锁**：多实例部署时，使用 Redis Store + 分布式锁避免同一任务重复执行。
2. **任务超时**：当前无超时控制，建议对长任务设置 `misfire_grace_time` 或超时装饰器。
3. **任务依赖**：APScheduler 原生不支持 DAG，复杂依赖建议引入 Celery 或 Airflow。
4. **去除 eval**：改为注册表 `TASK_REGISTRY = {"my_task": hello_task}`，按 key 查找。
