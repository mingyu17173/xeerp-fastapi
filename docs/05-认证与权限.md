# 05 · 认证与权限

> 核心源码：`system/service/login_service.py`、`system/api/v1/login_controller.py`、`gateway/core/auth.py`

---

## 一、全局鉴权流程

```
前端 → Gateway.AuthMiddleware → JWT 校验 → 成功: 转发 → 下游 Service
                                        → 失败: 401 JSON
```

- **签发**：`system` 服务的 `/api/auth/login` 校验用户名/密码/验证码，签发 JWT
- **校验**：Gateway `AuthMiddleware` 对非白名单路径验证 Header `Authorization: Bearer <token>`
- **解析**：网关校验通过后把 payload 挂到 `request.state.user`，同时原始 Token 在 Header 中随请求转发给下游
- **过期续签**：Token 有效期默认 1440 分钟（24h），前端到期前可主动刷新

## 二、登录接口细节

### 2.1 请求参数

| 字段 | 说明 |
| ---- | ---- |
| `username` | 账号 |
| `password` | 密码（明文传输到后端由 bcrypt 验证） |
| `code` | 验证码值（可关闭） |
| `uuid` | 验证码会话 ID（对应 Redis 存储的正确答案） |
| `captcha_enabled` | 是否启用验证码（dev 模式/API 文档请求自动跳过） |

### 2.2 安全策略

| 策略 | 实现 |
| ---- | ---- |
| 密码错误计数 | Redis key `PASSWORD_ERROR_COUNT:{username}`，5 次锁定 10 分钟 |
| 账号锁定 | Redis key `ACCOUNT_LOCK:{username}`，期间拒绝登录 |
| IP 限制 | `__check_login_ip` 可配置 IP 白名单 |
| 验证码 | Redis 存储图片验证码答案，2 分钟过期 |
| 密码存储 | `passlib` bcrypt hash |
| Token 吊销 | Redis key `ACCESS_TOKEN:{session_id}`，退出时删除 |

### 2.3 成功响应

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "eyJ...",
    "token_type": "bearer"
  },
  "success": true
}
```

## 四、密码工具（`utils/pwd_util.py`）

```python
class PwdUtil:
    @staticmethod
    def get_password_hash(password: str) -> str:
        return pwd_context.hash(password)

    @staticmethod
    def verify_password(plain_password: str, hashed_password: str) -> bool:
        return pwd_context.verify(plain_password, hashed_password)
```

使用 `CryptContext(schemes=["bcrypt"])` 进行哈希，不可逆。

## 五、权限模型（RBAC）

XEERP 采用经典 RBAC0 + 数据权限：

```
用户 (sys_user)
  ├── 角色 (sys_role)          ← 中间表 sys_user_role
  │     └── 菜单/按钮权限 (sys_menu) ← 中间表 sys_role_menu
  └── 部门 (sys_dept)
        └── 数据权限范围（全部 / 本级 / 本级及以下 / 自定义）
```

- **菜单权限**：前端侧控制菜单项和按钮可见性（`router_service` 返回用户可见路由树）
- **数据权限**：service 层通过 `@DataScope` 注解/方法，在 SQL WHERE 追加部门过滤条件
- **超级管理员**：`user_id = 1` 拥有所有权限，跳过任何权限校验

### 5.1 相关接口

| 路径 | 方法 | 用途 |

## 七、扩展建议

1. **前后端约定**：前端 401 状态码跳转登录页，403 弹出"无权限"。
2. **Token 刷新**：当前无刷新接口，建议增加 `POST /api/auth/refresh`，延长 Token 有效期。
3. **双 Token 方案**：短有效期 access_token + 长有效期 refresh_token，提升安全性。
4. **API Key**：对接第三方系统可增加 `X-API-Key` 鉴权旁路，绕过 JWT 验证码流程。
